# Sequence Visualiser

This project takes enrolment sequences generated by [transition-checker](https://github.com/llimeht/transition-checker) and associated rules files, and turns them into human-readable sequences.

It can visualise enrolment sequence plan files as:

- HTML (scrollable, year sections with period subsections)
- PDF (fixed-grid first page, optional configurable second page)

The CLI can process multiple plan files in one run (for example, shell globs).

## Current behavior

- Batch mode: continue processing other plans if one plan fails.
- Error handling: fail fast per bad plan, return non-zero if any plan failed.
- Course display: show course code and title; show UoC only when not equal to 6.
- HTML: year sections default to expanded.
- PDF: fixed period columns per year using inferred calendar model.
- Supported period sequences:
  - Trimesters standard: Term 1, Term 2, Term 3
  - Trimesters extended: Summer Term, Term 1, Term 2, Term 3
  - Semesters standard: Semester 1, Semester 2
  - Semesters extended: Summer Term, Semester 1, Winter Term, Semester 2
- When any extended label appears in a calendar family, all in-scope years for that family render the extended period sequence with blank placeholders for missing periods.
- PDF and HTML period colours are configurable via `templates/config/*.json` (model-aware keys with fallback to terms/semesters keys).

## Install

```bash
git clone https://github.com/llimeht/sequence-visualiser
cd sequence-visualiser
python -m venv .venv
source .venv/bin/activate
python -m pip install -e .
```

Note that you will need:

- enrolment plans in json format, as extracted by `extract-plans` (or `plan-validate`) using the [transition checker](https://github.com/llimeht/transition-checker) tools (either a symlink to the `plans` directory or specify the path to those outputs)
- a metadata source - plan metadata embedded in the plan files by `transition-checker` version 0.6.0 or newer is recommended and is the default. Alternatively the metadata can be obtained form the degree rules files or provided in a CSV file; see Metadata discovery below.

## Run

Single file:

```bash
sequence-visualiser plans/CEIC/CEICAH3707_2026_T1.json \
    --output-dir output --formats both
```

Multiple files (shell-expanded):

```bash
sequence-visualiser plans/CEIC/CEICAH3707_2026_*.json \
    --output-dir output --formats html,pdf
```

Overriding the metadata for the plans using a spreadsheet (CSV file);
default is to use the embedded metadata in the plan files:

```bash
sequence-visualiser plans/CEIC/CEICAH3707_2026_T1.json \
  --metadata-source spreadsheet \
  --metadata-map metadata/program-metadata.csv \
  --output-dir output --formats both
```

Plans that have missing titles or UoC for courses can have these data filled in using the same
catalogue files as used by the `transition-checker`. For example:

```bash
sequence-visualiser plans/CEIC/CEICAH3707_2026_T1.json \
    --catalogue plans/catalogue.json \
    --catalogue-overrides plans/CEIC/catalogue_overrides.json
```

### CLI options

- Positional:
  - `plan_files`: one or more plan JSON files
- Optional:
  - `--output-dir` (default: `output`)
  - `--rules-dir` (default: `rules`)
  - `--metadata-source` values: `rules`, `plan`, `spreadsheet` (default: `plan`)
  - `--metadata-map` CSV/TSV mapping file (required when `--metadata-source spreadsheet`)
  - `--templates-dir` (default: `templates`)
  - `--config-dir` (default: `templates/config`)
  - `--template-overrides-dir` (default: `template-overrides/config`)
  - `--formats` values: `html`, `pdf`, `both`, or comma-separated list (default: both)

## Metadata discovery

The visualiser needs program metadata (program name/id, specialisation name/code data, etc.)
for rendering and config-layer selection. Metadata is resolved using exactly one source mode.

### Source modes

1. `plan` (default)
    - Uses `program_metadata` embedded in each plan JSON.
    - No rule file lookup is performed.
    - Needs plan files generated by `transition-checker` version 0.6.0 or newer.
2. `rules`
    - Uses rule files in `--rules-dir`.
    - Selects exact matching rule file first, then year-ranged rule file.
3. `spreadsheet`
    - Uses a CSV/TSV mapping file (`--metadata-map`) keyed by plan filename.
    - No rule file lookup is performed.

### Embedded plan metadata (`--metadata-source plan`)

Add a `program_metadata` object to the plan JSON:

- `plan_code` (required)
- `program_id` (required; canonical)
- `program_name` (required)
- `specialisation_codes` (required list)
- `specialisation_names` (required list)
- `degree_code` (optional alias; if provided, must equal `program_id`)

Example:

```json
"program_metadata": {
  "plan_code": "CEICAH3707",
  "program_id": "3707",
  "program_name": "Bachelor of Engineering (Honours)",
  "specialisation_codes": ["CEICAH"],
  "specialisation_names": ["Chemical Engineering"]
}
```

### Spreadsheet metadata (`--metadata-source spreadsheet`)

Required columns (in recommended order):

1. `plan_filename`
2. `plan_code`
3. `program_id`
4. `program_name`
5. `specialisation_codes` (list)
6. `specialisation_names` (list)

List fields accept semicolon-delimited values (for example `MATSM1;CEICM1`) and can
also be provided as JSON-array text.

Validation behavior:

- `plan_filename` must uniquely identify one row per plan.
- `plan_code`, each `specialisation_codes` entry, and `program_id` must be valid
  uppercase alphanumeric identifiers consistent with current code parsing.
- Spreadsheet mode fails fast when required columns are missing or required values are empty.

### Course override files

Course display overrides can be used to change the displayed course code, course title, or even
hide a course from display. This is needed for dealing with synthetic course codes that are
used to represent elective buckets or other special cases in the enrolment sequences.
The overrides can be split across multiple files and are merged automatically.

Supported file names in each config directory (`templates/config` and `template-overrides/config`):

- `course-overrides.json` (base/common entries)
- `course-overrides-*.json` (split files such as `course-overrides-ceic.json`, `course-overrides-mech.json`)

Merge order and precedence:

1. Files in `--config-dir` are loaded first
2. Within a directory, `course-overrides.json` is loaded first
3. Then `course-overrides-*.json` files are loaded in alphabetical order
4. Files in `--template-overrides-dir` are loaded after `--config-dir` using the same order

If the same override key appears multiple times, the last loaded entry wins.
A warning is logged if any duplicate course code is found.

A setting both the course code and course title to `""` (empty string) will hide the course from display in the output.

## Supported markup and formatting

Limited support is provided for a subset of HTML in the notes fields within the plans and within the text fields of the templates. The following are supported:

- `<b>...</b>` for bold text
- `<i>...</i>` for italic text
- `<a href="...">...</a>` for hyperlinks

### Repository layout

- `src/sequence_visualiser`: CLI and rendering code
- `templates`: HTML template, config layers, and assets
- `rules`: degree rule files used for metadata resolution; this is likely from the [transition checker rules repository](https://github.com/llimeht/transition-checker-rules)
- `plans`: input enrolment sequence files; this is likely from the outputs of you running the [transition checker](https://github.com/llimeht/transition-checker) tools (specifically `plan-validate` or `extract-plans`)
- `tests`: unit and CLI tests
- `template-overrides`: your local branded assets including logos, style sheets, course-overrides, colours, footers; ignored by git.
- `output/`: generated output files; ignored by git.
